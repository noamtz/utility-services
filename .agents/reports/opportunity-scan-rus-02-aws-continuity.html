Make the AWS account identity impossible to forget

The RUS-02 implementation was locally complete, but its infrastructure preview stopped because the agent invoked SST without the AWS identity contract established during RUS-01. The immediate credential error was real; the deeper failure was that the repository did not carry forward the account, principal, profile, and Windows CA-bundle requirement.

What actually happened

  1. RUS-01 evidence showed account 162067902192 in il-central-1.
  2. A prior session verified arn:aws:iam::162067902192:user/ntz-cli through profile ntz-cli.
  3. That verification required the AWS CLI CA bundle at C:\Program Files\Amazon\AWSCLIV2\awscli\botocore\cacert.pem.
  4. RUS-02 called the wrapper with no explicit profile or CA bundle, so AWS fell through to an unrelated, expired default chain.
  5. The follow-up diagnosis tested ntz-cli without the known CA-bundle setting and incorrectly treated the resulting failure as invalid credentials.
“We need to have a continuation between Codex sessions and issues work to know how to access the target account.”

The smallest durable change

Choose

Repository rule + SST account preflight

Put the non-secret identity contract in root AGENTS.md so every Codex run receives it. Make the guarded SST wrapper set the required profile/region/CA bundle and verify the exact STS account and principal before any networked SST operation.

Why not a new skill?

This is an invariant, not an optional multi-step workflow. A skill would need to trigger correctly and could still be skipped. The wrapper is closer to the risky operation and protects both agents and humans.

Why not only documentation?

Documentation restores context but cannot prevent profile fallback. The preflight turns the target account from remembered advice into an executable condition.

Why not a generic Codex hook?

A shell-command matcher would be broad, fragile, and Codex-specific. Enforcing the identity in the repository’s existing SST wrapper covers the actual infrastructure boundary with less policy surface.

Expected future behavior

A new issue or Codex session immediately knows the AWS target and verification recipe. infra:install remains local. Before diff, dev, or deploy, the wrapper authenticates only as ntz-cli, rejects any other account or principal, and never prints credential values. Authentication failure reports the required profile and CA-bundle remediation instead of probing unrelated profiles.
